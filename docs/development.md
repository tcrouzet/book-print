# Configuration and development

The [main README](../README.md) introduces Bookbinder and its visual project editor. This page covers project files and development tools.

## Project files

Bookbinder reads the YAML properties at the start of `bookbinder.md` in the selected folder, or in the selected Markdown file's parent folder. Chapter properties do not override the project settings. Without a project, the title comes from the source filename or folder name. With no selected model, the language is French, EPUB leaves fonts to the reader and print formats default to EB Garamond from the shared library.

Use [bookbinder.example.md](../bookbinder.example.md) as a starting point, renaming it to `bookbinder.md`. YAML must be enclosed by two `---` lines at the beginning of the file. Nested settings can be edited in Obsidian's source mode. Text after the properties is preserved on save.

Settings → Project model lists Markdown models in the plugin's root `models/` folder. Download models from GitHub reads that folder from `tcrouzet/bookbinder` on `main`, validates every model for PDF, DOCX and EPUB, then adds missing files. Different local files are preserved and reported as conflicts. The selected filename is stored as `projectModel` in plugin settings. The [base model](../models/base.md) contains the manuscript's page, typography and rule settings for all formats. Models initialise new projects and exports without a project file; existing projects and clones retain their own settings. Title, author and rights are blanked when loading a model, and `filename` is removed so the new book derives its own output name. A new project's title field stays empty until entered.

Saving or cloning places book metadata and custom properties first, followed by `fusion`, `pdf`, `docx` and `epub`, in that order. Property names and values are preserved.

The note's `[Modifier le projet](obsidian://bookbinder)` link opens the visual editor. In reading mode, Bookbinder adds the vault and source note to the rendered link. Without those parameters, including in Live Preview, it uses the active project note. The saved link stays independent of the folder path and vault name.

`bookbinder.md` is excluded from assembly at every level of the selected hierarchy. The output basename comes from the optional top-level `filename` field. When it is missing or empty, `plugin/filename.ts` combines the last word of the first author’s name with the title. The initial elided French article `L’` or `L'` is omitted from the title. The shared normaliser produces lowercase ASCII words joined by hyphens, removes diacritics, handles common Latin ligatures, strips known export extensions and avoids Windows device names. Names are limited to 200 characters to leave room for extensions and version suffixes; `book` is the fallback when nothing remains. The extension is appended by the exporter.

The General file-name input stores a normalised custom value on input and displays it on blur. Its placeholder is recomputed when title or author changes; clearing the input removes the override. Filename settings are saved with the editable properties and preserved by cloning. Without a project or author, the source filename or folder name supplies the default title and slug.

When that filename already exists, the desktop dialog offers replacement, a numbered version or cancellation. Numbered names append `-2`, `-3` and so on, preserving the slug format and skipping occupied names. New files use exclusive creation, including when exports race; replacement requires an explicit choice and happens after successful conversion. Calls without a confirmation callback create a numbered version. The exporter returns the generated path, or `undefined` on cancellation.

Cloning reads the selected `bookbinder.md` file, writes a new `bookbinder.md` and preserves its properties and Markdown body. File paths in `cover`, `cover-background`, the format-specific `fonts`/`css` settings become absolute paths to the original files. Library font references remain unchanged. No manuscript or resource files are copied by cloning. Existing destination projects are refused, and creation uses the same exclusive-write protection as a new project.

## Presentation properties

| Property | Purpose |
| --- | --- |
| `epub.page` | Top, bottom, left and right page margins, using `margin-top`, `margin-bottom`, `margin-left` and `margin-right`. |
| `epub.style` | Body text and the book's base typography. |
| `epub.headings` | Heading styles, from `h1` to `h6`. |
| `epub.styles` | Markdown styles such as `blockquote p`, `.smallcaps`, `sub` and `sup`. |
| `epub.rules` | First occurrence of any manuscript style in the book or after a heading. Paragraphs and headings also expose an after-heading first-character rule. |
| `epub.disabled-rules` | Style kinds with no contextual rule, such as `body`, `quote`, `h3`, `em` or `table`. Saved formatting remains available when reactivated. |
| `epub.css` | One custom CSS path or a list of paths, replacing the bundled base CSS. |
| `epub.fonts` | Technical font references derived from styles by the editor; also accepts resource file paths. Explicit resources remain supported for custom CSS. |
| `epub.toc-depth` | Table of contents depth, from 1 to 6; default 2. |
| `epub.toc` | Show a contents page in the reading order; default false. Reader navigation remains available. |
| `epub.split-level` | Heading level used to split the EPUB, from 1 to 6; default 2. |

PDF and DOCX each store optional `title-page: { copyright: false, character-count: false }` settings beside their `page` and `toc` settings. The Page panel exposes the two independent checkboxes. Copyright uses the common `rights` metadata. The shared reader counts Unicode code points in rendered manuscript text before adding generated colophon pages; it includes footnotes and normalises ASCII whitespace between text blocks. Markdown markup, link targets and project notes are excluded. Count labels follow the book language. Native export tests cover both checkboxes on/off, covers, accented text, notes and escaped copyright text.

PDF passes `characterCountDivisor: 1000` to that reader and displays the result rounded to the nearest whole thousand (`ksignes` in French); DOCX retains its exact count. PDF headings and whole-heading rules accept `folio: show` or `hide`. The Flow checkbox defaults to show and rules inherit their base heading's setting. A hidden-folio heading inserts a distinct e-TeX mark within its first line. The footer compares top and bottom marks to suppress pages containing those headings, following automatic line/page breaks and restoring the folio on continuation pages. A hide request wins when headings share a page. The title-page environment uses the empty page style throughout; standard double-page breaks reuse the existing blank-page parity command.

`pdf.styles[".bookbinder-colophon p"]` also accepts `page-position: one-third`. The PDF compiler extracts page flow into one colophon wrapper and leaves paragraph typography in the ordinary style. The writer places that wrapper before the TOC anchor and closes it after the attribution, so subsequent paragraphs do not create pages or repeat the offset. Positioning ignores the saved top margin without changing the project; an attribution-only colophon omits its otherwise redundant leading gap. EPUB and DOCX colophon settings remain unchanged.

Print top-margin inputs remain enabled while one-third positioning is active. Editing one clears the base style's positioning, or stores `page-position: normal` in a contextual rule to override an inherited position. The inspector updates its position and break controls without replacing the input, preserving focus and unit entry. PDF/DOCX validation accepts the explicit normal override; preview CSS clears inherited positioning padding. The saved page-break/parity setting remains intact. The PDF colophon uses the same input behaviour.

The same PDF colophon style accepts `folio: show` or `hide`. Hiding applies the empty page style inside the colophon wrapper, with explicit empty styles on its first and last pages so suppression survives the final group's closure. The preceding manuscript page retains its folio; long colophons suppress every continuation page and the attribution page too.

Custom stylesheet paths and split level are advanced YAML properties. The visual editor offers Page, Styles and Rules; it preserves existing advanced properties when saving. **Page → Table of contents** exposes `toc` and `toc-depth` independently for EPUB, PDF and DOCX. Depth includes headings from level 1 through the chosen level, from 1 to 6 (default 2). PDF and DOCX default to `toc: true`; EPUB defaults to false to keep its existing navigation-only output. Disabling the visible EPUB contents page preserves navigation and its configured depth. Print formats disable the depth control when the TOC is off and retain its value for reactivation.

Style properties accept `font-family`, `font-size`, `line-height`, `text-align`, `text-indent`, the four `margin-*` properties, `color`, `font-weight`, `font-style`, `letter-spacing`, `display` and `page-break-before`. An omitted property means Auto. Body text size is applied once; paragraphs inherit it. The bundled heading styles have no top padding: a zero top margin leaves no additional gap unless start-of-page spacing is explicitly enabled. Export does not insert paragraphs or spacers before headings.

Character buttons also support `vertical-align: baseline | super | sub`, `text-transform: none | uppercase` and `font-variant: normal | small-caps` in all formats and contextual rules. Position and case buttons toggle on/off; resetting the style restores inheritance. EPUB bold/italic retain their Auto/on/off cycle, with the inherited state marked by a dot; tooltips name every state. EPUB uses native CSS and inline wrappers for paragraph positioning. PDF formats words separately so raised/lowered paragraphs remain breakable, and DOCX uses native run properties without changing the Markdown source.

Headings and the book title default to normal leading (1.2 times their own font size), independently of fixed body leading. PDF/DOCX paragraph styles and whole-paragraph rules also accept `hyphens: auto | none`, exposed as Automatic hyphenation in the Paragraph inspector. Body text allows hyphenation by default; headings do not. PDF applies a local TeX hyphenation penalty, leaving literal compound-word hyphens unchanged. DOCX enables native document hyphenation and uses `w:suppressAutoHyphens` in the paragraph styles, including inherited and conditional styles. These settings do not insert characters in the source text.

The reader wraps second and subsequent paragraphs of the same base style in `div.bookbinder-continued-KIND`. Inline emphasis and first-after-heading variants do not change the base paragraph identity. Adjacent `BlockQuote` containers pass their previous and last paragraph styles through the child flow, so quote paragraphs separated by blank lines or note boundaries still continue the same sequence. Tracking is local to each text flow, resets at headings or other block styles, and spans notes assembled without a separator. An explicit note page break starts a fresh run; its later paragraphs still continue that run. EPUB clears only the wrapped paragraph's top margin, and preview adjacency rules show the same effect. PDF uses the compiled `continuedBefore` variant while retaining `after`; in footnotes, an initial top margin uses a strut so it does not become deferred space below the first line. DOCX derives a paragraph style with only `w:before="0"`, inheriting the existing bottom margin and typography. These are export adjustments; project margin values are preserved. The fixture `scripts/fixtures/paragraph-spacing.md` checks runs of 2 and 3 paragraphs, quotes within and across separate blocks, style changes, footnotes and colophon spacing in the native exports.

For other styles and contextual rules, `font-family: body` and `font-size: body` are explicit references to the base text, distinct from Auto. They are saved as references, not copied values, and unit normalisation leaves them intact. The base `style` rejects self-references. The font menu offers Body text; the size field offers Auto, Body text and Custom. Print controls still display the model's concrete size in Auto. Font references are not font-library entries and do not create duplicate resources. Shared resolution feeds PDF and DOCX, including inline styles, heading rules and initial characters. EPUB resolves an explicit body family to that same family; body Auto uses the reading system's initial font. Body-relative sizes use root-relative lengths so a styled ancestor cannot multiply the size; [Kindle Enhanced Typesetting supports rem](https://kdp.amazon.com/en_US/help/topic/GB5GDY7WAJDN9GFK). A body size in em or percent is converted to rem for the reference; absolute sizes remain absolute. No CSS variables or EPUB JavaScript are required.

The Tracking field displays thousandths of an em without a unit suffix: `+10` stores `letter-spacing: 0.01em`, in EPUB, PDF and DOCX alike. Changing the font size preserves this relative value. Previously stored absolute values are displayed as their relative equivalent without rewriting them until edited. EPUB keeps Auto when unset; print formats show their effective spacing. The exporters convert em to CSS letter-spacing, fontspec LetterSpace percentages or Word twentieths of a point.

EPUB controls use em. On saving through the editor, absolute values are converted to em using the loaded presentation. Bold and italic cycle through Auto, enabled and disabled. A style hidden in the export remains visible in the editor so it can be selected and changed. The preview does not modify the manuscript.

Absent presentation properties mean Auto. Opening or saving the editor never fills them from computed preview values: browser fonts, colours and sizes must not become explicit project settings. Saving normalises explicit dimensions to em and preserves missing properties. Previously saved explicit settings remain editable and can be cleared to Auto.

`epub.separator`, `pdf.separator` and `docx.separator` optionally contain literal characters for Markdown thematic breaks, independently per format. Omitting the setting keeps the line. The shared reader renders characters inside `div.bookbinder-separator`; each format's `styles.hr` applies to both forms. The preview exposes Line/Characters and a text field when editing the Separator style in all three formats. Characters are inserted as text, with no Markdown or HTML interpretation; print writers apply the separator's font, size, alignment and margins. Assembly separators remain a separate `fusion.noteSeparator` setting.

Heading styles `epub.headings.h1` through `h6`, the book-title style `epub.styles.h1.title` and heading rules accept `page-position: one-third`. EPUB exposes this as **Flow → Heading position → Space at top of page**, with **Space above heading (mm)**. `page-offset` stores a fixed distance, defaulting to `50mm`. It accepts zero and absolute lengths up to 300 mm; relative lengths in project data are rejected so the gap cannot depend on text size. Input units are converted once to mm; an em entered in this field uses a fixed 12 pt conversion reference. Export adds `page-break-before:always`, `break-before:page`, `margin-top:0` and `padding-top` with the distance normalised to mm. [Kindle Enhanced Typesetting supports millimetres for padding](https://kdp.amazon.com/en_US/help/topic/GB5GDY7WAJDN9GFK). Padding retains space at the page boundary without inserting hidden paragraphs or altering the heading's font. The gap stays constant when either heading or reader font size changes. The ordinary `margin-top` is kept inactive and unmodified until returning to Auto. Clearing the fixed offset restores 50 mm. PDF/DOCX retain their existing one-third position. A fixed distance does not track an exact fraction of different screens; check the result on the target Kindle. Neither internal positioning key is emitted as a CSS property.

The Book title style targets Pandoc’s existing `h1.title` on `title_page.xhtml`. Chapter-level h1 overrides use `h1:not(.title)` so their formatting does not affect the book title. Its preview and formatting controls use the same style editor as other elements. The generated JPEG cover remains configured through the cover settings.

The editable top-level `colophon` property is a Markdown string, exposed under Publication. Before contextual rules are applied, the reader appends a level-1 boundary labelled with the book-language translation of Colophon and the `unnumbered` and `bookbinder-colophon-boundary` classes. Generated presentation CSS hides that boundary heading on the page. Both EPUB navigation and NCX include its link to the final spine item at every supported split level, without consuming after-heading paragraph rules or generating an intermediate Markdown file. Existing chapter footnotes stay before this page. Personal text and the credit are parsed separately, so a user’s Markdown cannot absorb the attribution into a list or code block. Both are wrapped in `div.bookbinder-colophon`; the Colophon style maps to `epub.styles[".bookbinder-colophon p"]` and controls paragraph typography. It starts on Auto and appears in the alphabetical style list, with a translated preview. Credit paragraphs keep their centred alignment, zero margins and zero indent through a more specific selector; the credit container retains its smaller size and gap. The credit is placed in `div.bookbinder-credit`, centred, with a 3em top margin and smaller text. It uses `generatedByBookbinderOn` with a `{date}` parameter, formatted from the generation time in the book’s language, independently of the publication date. The default credit links to `https://community.obsidian.md/plugins/bookbinder`. Hyperlinks are underlined by default and inherit the text colour.

Before merging each note, the reader reserves its declared identifiers and makes them unique across the book, retaining unused identifiers and adding numerical suffixes to collisions. It updates that note’s local fragment links, including percent-encoded fragments. This covers repeated chapter or part headings and explicit IDs without creating collisions with existing spans or other anchors. The final Pandoc EPUB and NCX navigation therefore point to the correct occurrence of repeated titles. Footnotes remain parsed within each source note.

The bundled presentation starts a new page at heading levels 1 to 4 and removes the first-line indent from the first body paragraph after a heading. It leaves the body font, size and colour to the reading app, includes no font declarations, and imposes no colour or initial-letter formatting. Links and separators inherit the text colour. The preview shows default text in black on white; those preview colours are not exported. Project settings can add these effects. The interior book title has its own style; generated JPEG cover text and technical punctuation elements are not offered as Markdown styles.

The `pdf` and `docx` sections retain separate presentation settings, with page margins in millimetres and typography in points. Both exporters use the same print model; their previews are indicative.

## PDF layout and export

`PDF → Page → Paper size` stores `pdf.page.paper-size` as `a4`, `a5` or `custom`. A5 is the default. Custom dimensions use `paper-width` and `paper-height`, such as `160mm` and `240mm`. `pdf.page.page-mode` selects `single` (default) or `double`. Single pages use `margin-left` and `margin-right`; facing pages use `margin-inner` and `margin-outer`, falling back to the existing left/right values when unspecified. Top and bottom stay unchanged. Unspecified margins display the model’s 20 mm. The editor groups Top/Bottom and the horizontal margins into two rows, followed by `binding-offset` in mm (default 0). That offset adds to the left margin for single pages and to the inner margin for facing pages. The validator includes the binding allowance when checking the remaining text width. The exporter selects LaTeX’s `oneside` or `twoside` mode and geometry’s `bindingoffset`; facing-page margins mirror on even pages. The preview illustrates a recto page. Switching modes preserves the settings of both layouts. DOCX exposes the same controls and keys in `docx.page`.

`pdf.style`, `pdf.headings`, `pdf.styles`, `pdf.rules` and `pdf.disabled-rules` follow the EPUB structure. PDF uses the complete Markdown style list and contextual paragraph/first-character rules, with points for typography. Its body defaults to EB Garamond at 11 pt with Auto leading, 1.2 times the font size. The empty leading field displays Auto and stays unset after saving or losing focus; entering a point value fixes it, and clearing restores Auto. A numeric YAML `line-height` remains a relative multiplier, while a value such as `18pt` is absolute. DOCX writes [native relative line spacing](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.spacingbetweenlines.line?view=openxml-3.0.1) for automatic or relative leading and exact twentieths of a point for absolute values. Heading and book-title styles accept `page-position: one-third`. PDF values stay independent from EPUB. The visual preview illustrates formatting; XeLaTeX determines pagination.

For `pdf.headings.h1` through `h6` and their DOCX equivalents, `page-break-before` accepts `auto` (no break), `always` (next page), `left` (even page) or `right` (odd page). The Flow inspector exposes these choices on heading styles. A heading at `page-position: one-third` keeps the parity choice and requires a break; its stored No break setting is preserved while that position is active. PDF shares the even/odd page commands with note separators and leaves inserted parity pages blank without folios. Its page counter follows physical pages after the title page and the transition to the body, so numbering and parity agree in both single and facing layouts. DOCX uses even/odd section starts and disables the ordinary paragraph page break on those headings, keeping section geometry and footer settings. The chapter heading remains a native Word heading for the TOC. EPUB controls retain their existing behaviour.

PDF and DOCX controls display values from `pdfStyleValues` in `plugin/pdf-presentation.ts`, sharing the exporters’ style definitions; unset leading displays Auto. `applyDefaultFont` in `plugin/presentation.ts` declares `library:EBGaramond-Regular.otf` as the default body font when none is specified. Parsing, editor initialization and style resets use this helper. This declaration goes through the same library, `fontsInStyles`, dropdown and used-fonts sorting as EPUB; it appears above the separator. Existing explicit font choices are preserved. Bold and italic have two states; alignment, colour, visibility and page breaks show effective values. Clearing other numbers restores their inherited values on blur; resetting removes overrides and restores the default font. Unspecified numeric defaults remain implicit, so inherited styles follow later base-style changes. EPUB retains its Auto controls.

Print page properties `folio-position` and `folio-offset` control the footer: `none`, `left`, `center` (default), `right`, `inner` or `outer`, and a distance from the bottom in mm (default `10mm`). Inner/outer mirror on even pages in double-page mode. `styles[".bookbinder-folio"]` defines the Folio typography; alignment controls also update the page position. PDF generates odd/even plain footers using the existing style formatter. The first book page stays unnumbered; no page-break formatting is applied inside a footer.

## DOCX export

`plugin/docx.ts` uses the shared source preparation, font library, print model and output replacement logic. `plugin/docx-presentation.ts` maps the print styles to Word paragraph and character styles, page geometry and footer fields. The bundled `scripts/lua/docx.lua` writer delegates document creation to Pandoc’s native DOCX writer and edits the package using [Pandoc’s built-in ZIP module](https://pandoc.org/lua-filters.html#module-pandoc.zip). A temporary reference document supplies page dimensions for images; table grids fit the printable width, including the binding allowance. No additional archive executable, Python, LaTeX or user-authored Word template is required.

DOCX preserves per-note footnotes and unique heading bookmarks, applies Markdown and contextual styles, and places an optional cover before the table of contents. The final colophon has no visible heading; when a TOC is enabled, a TC field includes it. Footers contain PAGE fields, with separate odd/even alignment and a blank first-page footer. Facing-page margins use Word’s mirror-margins setting. Only a requested TOC enables `updateFields` on opening; without a TOC, the unused TC field is omitted and `updateFields` is false. Page numbers, the TOC and final pagination depend on the word processor.

Handwritten paragraph properties follow the ECMA-376 child order, including `keepNext`, `pageBreakBefore`, spacing, indentation, alignment and outline level. Settings are inserted into the native document in their schema order while preserving Pandoc's settings. Each package content type is declared once; Pandoc already supplies the obfuscated-font content type. DOCX regression checks cover those constraints as well as XML parsing, archive integrity and relationship/font handling. Full manuscript and fixture parts were additionally checked against the official ECMA-376 transitional schemas; those schemas are development-only validation data and are not plugin resources.

Selected OTF/TTF faces are embedded as complete obfuscated font parts, using family names and regular/bold/italic/bold-italic declarations from the same font metadata as EPUB/PDF. The OS/2 embedding flags must permit editable embedding; restricted, preview-only and bitmap-only embedding are refused before replacing an existing output. Native Word rendering is not covered by the automated package/XML checks.

`plugin/length-input.ts` shares measurement parsing, conversion and input validation between the style editor and paper controls. It accepts optional whitespace, decimal commas and physical or relative units. Values convert to the field’s unit on input and display the converted number on blur. Relative conversions use the element’s font context; EPUB page margins use the root font, matching the preview’s `@page` handling. PDF uses the model’s font sizes. Stored input values are rounded to six decimal places. Invalid or out-of-range input preserves the previous setting and blocks saving through native form validity.

`plugin/pdf-presentation.ts` converts supported style values into LaTeX commands. `scripts/lua/pdf.lua` applies them to the Markdown structure and contextual markers produced by the shared reader. The self-contained `scripts/latex/book.latex` template is adapted from Pandoc’s default template under its BSD 3-clause licence, retained in the template. It contains its partials and is compiled into the plugin. Users need no editable LaTeX template.

`Book to PDF` uses the same in-memory assembly, source-relative images, project exclusion and overwrite handling as EPUB. It detects Pandoc and XeLaTeX from the configured paths, stages resources beside the output and enables no shell escape. The title page, table of contents, local source footnotes and final colophon are included. OTF/TTF fonts declared in PDF styles are loaded through the shared `loadFont` helper and staged without conversion. The shared `fontVariants` resolver associates the family’s real faces; fontspec receives explicit `BoldFont`, `ItalicFont` and `BoldItalicFont` options. No artificial bold or slant is requested. The selected body font also becomes the LaTeX main font for the table of contents and page numbers. WOFF/WOFF2 are reserved for EPUB. Missing fonts explain how to import them or install the package from settings, preserving the previous PDF. A selected cover image replaces the typographic title page.

## Covers and fonts

`cover` selects an existing image. If it is empty, Bookbinder renders a JPEG cover at 1600 × 2400 pixels: a vertical pattern, author, red title, subtitle and a footer with the book's length and date. Use `\n` in the title for line breaks. `cover-background` supplies an optional background image.

Paths in `cover`, `cover-background` and `epub.css` are relative to the project file. Imported fonts use `library:filename.ttf` references, resolved inside the plugin’s `data/_fonts/` directory. Custom stylesheet font resources can use relative or absolute file paths.

The bundled EPUB CSS requires no fonts. All installed library fonts are listed directly in the format and contextual-rule style editors. A style declaration automatically selects its font; there is no separate activation list. The editor derives each format’s font resources from its body, heading, named and contextual-rule styles. Importing alone does not select a font. Auto and style resets remove a font from the resources when no style declares it, keeping the file in the library and the preview cache. The exporter also resolves style declarations against the shared library, so manually edited projects need no separate `epub.fonts` list for library fonts. Unused font resources are ignored when using the built-in CSS. Projects supplying custom CSS keep their explicitly declared font resources. EPUB body text stays on Auto until explicitly changed.

Family grouping and variant selection are shared by EPUB, PDF and DOCX controls through `plugin/presentation.ts`. `fontChoices` lists one representative per family; `resolveFontFamilies` expresses selected faces as a family plus bold/italic declarations. Existing face selections retain their formatting when normalized. `fontsInStyles` adds the selected family’s available regular, bold, italic and bold italic resources. EPUB CSS declares them under the same family with their actual weights and styles; the preview registers native FontFace objects with the same descriptors. Choosing a family loads its variants together. PDF uses the same resolution with fontspec. `detectFontFace` reads family names from OpenType name IDs 21/16/1 and weight/slope from OS/2, including compressed WOFF/WOFF2. When metadata is absent, standard Regular/Bold/Italic/BoldItalic filename suffixes provide a fallback. Face metadata stays in memory, without a project schema change. Only used families are loaded into previews or embedded in books; unrelated fonts stay in the library.

The optional package lives in one flat [`fonts/`](../fonts/README.md) folder. Each family has a `Family.md` usage note and `Family.LICENSE.txt` licence beside its font files. `fonts/catalog.json` classifies families as `serif`, `sans-serif` or `symbol`; the catalogue and style lists show that type after the name. After editing the package contents or catalogue, run `node scripts/build-font-package.mjs` to rebuild the separate gzip-compressed JSON download and its SHA-256 manifest. Commit the source folder, catalogue and package together. The download is `bookbinder-fonts.json.gz`. Publish these files to the repository’s main branch to enable the raw GitHub URL compiled into the plugin; no release workflow change is required. Normal plugin assets contain the catalogue without the font binaries. A source checkout uses its local package when present. Released plugins fetch it on demand through Obsidian’s request API. Native Node gzip decoding needs no shell command, archive tool or additional dependency. The installer checks the archive and every file against the compiled manifest before writing, refuses conflicting files, and installs fonts into `data/_fonts/`, with notes/licences named `_package-Family.md` and `_package-Family.LICENSE.txt` in the same flat folder. A package installation never assigns fonts to projects automatically. `npm test` covers package integrity and installation; `test:ui` loads all supplied fonts through Chrome’s native FontFace API.

Personal font import is available in general settings through `plugin/font-import.ts`. It detects Serif/Sans serif/Symbol from the OS/2 table (PANOSE, IBM family class and symbol code-page flag) through plugin/font-metadata.ts, including compressed WOFF and WOFF2 containers. Existing library classifications take precedence, and the package catalogue supplies a fallback for known filenames. Recognized selections import directly; only unclassified fonts open the type picker. Every selected font still passes native FontFace validation before any font is saved through the shared library helper. The type is a JSON string in `FontFile.otf.type.json` beside the font, written atomically. Packaged fonts use the compiled catalogue as their default classification. Reimporting an identical file preserves its stored classification; different bytes with the same filename are refused. Personal fonts join the same alphabetical catalogue, and the style editor receives their persisted types without changing project font identifiers.

Imported fonts are validated and saved immediately in the shared library; cancelling project edits keeps those imports available. The library reads font headers for grouping; only used families load into the previews. Fonts declared in styles and their variants are embedded in the EPUB. Identical imports reuse the existing file; a different font with the same filename is refused. Clearing a style’s font declaration preserves the library file.

The repository’s private-file rule ignores `data/_fonts/`.

## Markdown assembly

The `fusion` section controls filename exclusions and the Markdown separator between notes. Its defaults exclude names containing `_` and notes named `sortspec`. Project notes are always excluded.

`fusion.noteSeparator` accepts `''` (no separator), `page`, `even` or `odd`. Page breaks apply before the first block of each following non-empty note, with no extra break before the first note or after the last. EPUB output uses `page-break-before` and `break-before`; even and odd request left and right pages, which reading apps may render as ordinary page breaks. Existing custom Markdown separators remain supported and are inserted only between notes.

HTML comments and Obsidian `%%…%%` comments are omitted. Markdown `~~strikethrough~~` is preserved. Folder Fusion markers such as `@@`, `££`, `€€`, `--…--` and `\newpage` do not create special styles.

Standard Markdown images and Obsidian `![[image.png]]` embeds are supported. Each chapter retains its own relative image paths and footnotes. Embedded notes such as `![[chapter]]` are not expanded.

Pandoc's `[text]{.smallcaps}`, `H~2~O` and `m^2^` produce small caps, subscripts and superscripts. Indented blocks, beginning with a tab or at least four spaces, use the Tabulation style. Their contents retain Markdown emphasis and line breaks. A fenced block with the `.tab` class also selects this style:

````markdown
```{.tab}
    A tabulated line
```
````

Fenced code blocks without `.tab` keep their literal contents. The shared reader parses Tabulation before contextual rules, so its inline styles participate in the same first-occurrence tracking. The EPUB tabulation filter retains those inline nodes for Pandoc's writer and runs before the punctuation filter. The Markdown sources are assembled in memory; no merged Markdown file is written. Temporary export resources are removed after conversion. A failed conversion preserves the last successful output.

## Project settings

A project is a `bookbinder.md` note. Its opener uses `obsidian://bookbinder`. Unknown style, rule and assembly settings are rejected rather than converted or discarded. Body text belongs in `epub.style`, page margins in `epub.page`, and contextual rules in `epub.rules`.

Rules retain `.bookbinder-after-heading-body + p`, `blockquote .bookbinder-after-heading-quote + p`, `section.footnotes .bookbinder-after-heading-footnote + p` and `.bookbinder-after-heading-tab + p.tab`. Other styles use definitions from `plugin/book-styles.ts`, such as `.bookbinder-rule-h3` and `.bookbinder-rule-em > em`. `ruleDefinitions` is shared by the reader and print writers. New markers are emitted only for configured rules; legacy paragraph markers remain hidden. Initial occurrences count before any heading, and the state spans the assembled notes. All non-heading styles reset after headings 1–6; heading styles reset only after a higher-level heading. H3 therefore applies initially and after H1/H2, but not again after H3/H4. Append `::first-letter` for paragraph and heading initials. Lists, table cells and image captions do not consume the body-text rule. Book-title rules apply to the generated title; folios are outside manuscript contextual rules. The generated colophon boundary and attribution do not consume or reset these rules.

Each manuscript style also offers **First “style” in the book**, using the same selector structure with `bookbinder-first-KIND` markers. Its shared reader definition has `scope: "book"`; this state spans all assembled notes and never resets at a heading. Both scopes share one wrapper when they coincide, avoiding multiplied relative font sizes. First-in-book settings override conflicting after-heading settings and retain the others. Print compilers merge those properties and resolve any after-heading initial character against the resulting paragraph size. EPUB emits first-in-book CSS last. Generated title rules use the same precedence; **No rule** disables both scopes for that style. The `first-in-book.md` fixture checks heading resets, separate notes, relative sizes, initials and print page breaks.

PDF rules replace the base style's compiled formatting so a conditional `page-break-before: auto` can cancel its break. DOCX keeps native heading bookmarks and outline levels while assigning the conditional Word style, with odd/even section breaks handled like normal heading styles. Native code paragraphs receive their configured rule style after writing. List and table rules provide the inherited style for their content; explicit child formatting takes precedence.

## Interface languages

`plugin/i18n.ts` receives Obsidian’s public `getLanguage()` value when the plugin loads. It resolves the requested locale, its base language, then English. French and English are plain JSON catalogues in `locales/fr.json` and `locales/en.json`. They are bundled into `main.js`, and `plugin/locale-files.ts` reads editable copies from the installed plugin’s `locales/` folder before registering the interface. Missing files are created from the bundled defaults; existing files are never overwritten. Editing the JSON and reloading Bookbinder changes the interface without rebuilding or changing the release assets. Interface text, accessibility labels, examples, errors and dialogs use these catalogues. Style lists and language names use the selected locale for display and sorting.

Use `t(messageId, { namedParameters })` for new interface text. Message IDs are stable camelCase names, such as `bodyText` and `bodyFontWarning`. Change only the JSON values when editing wording, and preserve named `{parameters}`. The loader validates text and placeholders before applying a catalogue. Missing keys use the bundled translation; invalid files remain intact, trigger a notice and use the complete bundled fallback for that language. `plugin/messages.d.ts` lists keys for TypeScript checking and contains no interface wording. New interface messages require entries in both JSON files and that declaration; adding a language also requires registering it in `plugin/i18n.ts`. `npm test` checks catalogue completeness, placeholders, runtime file edits, fallback and untranslated French literals; `test:ui` checks French and English controls, the body-font warning and layout.

Project keys, font identifiers and manuscript content stay independent of the interface language. The project’s `lang` still defaults to French and controls generated cover labels and dates. Stored project notes are preserved; the reading view translates recognised generated edit links and keeps custom labels.

## Tool detection

Opening Bookbinder's settings automatically detects Pandoc and XeLaTeX and compares their versions with official releases. If several installations are found, the newest detected version is selected. A custom executable path takes priority. **Save and check**, inside **Custom paths**, saves those paths and runs the checks again.

For Pandoc, supported installer links select a macOS Intel or Apple Silicon `.pkg`, or a Windows 64-bit `.msi`. LaTeX links point to official MacTeX, BasicTeX, MiKTeX or TeX Live pages. Current installations show **Up to date** without an installation link. Installed versions remain visible when the online comparison is unavailable.

TeX Live comparisons concern the annual release. Component updates use TeX Live Utility on macOS or the TeX Live manager on Windows. MiKTeX uses MiKTeX Console. The plugin does not install or update these tools automatically.

## Build and checks

Node.js 22.18 or later is required for the TypeScript checks. Plugin users do not need Node.js. The CI version is pinned in [`.nvmrc`](../.nvmrc).

```bash
npm ci --ignore-scripts
npm test
npm run build
node scripts/check-resources.mjs
```

[package.json](../package.json) also defines `test:ui`, `test:epub` and `test:release`.

- `test:ui` exercises the style inspector in Chrome: project links and accent colours, nested format tabs, independent settings, Markdown styles and contextual rules, em conversions, resizing, Auto values, keyboard access, dark theme and the font → saved project → EPUB path. It uses `/System/Library/Fonts/Supplemental/Times New Roman.ttf` by default; `BOOKBINDER_TEST_FONT` selects another font.
- `test:epub` creates a real EPUB with Pandoc and a cover rendered in Chrome. It checks chapter assembly, project exclusion, local footnotes, relative images, XML and preservation of the previous output after failure. It requires Pandoc, Chrome, `/usr/bin/unzip` and `/usr/bin/xmllint` on macOS. `BOOKBINDER_CHROME` selects the Chrome executable for both browser checks.
- `node scripts/check-pdf.mjs` creates real PDFs with Pandoc and XeLaTeX: A4, A5, custom dimensions, native title sizing, repeated headings in the table of contents, Markdown styles, local notes and preservation after failure or cancellation. It uses Poppler’s `pdfinfo`, `pdftotext` and `pdffonts` for output checks.
- `node scripts/check-docx.mjs` creates real DOCX files with Pandoc: A4, A5, custom dimensions, margins, binding, footer fields, Markdown styles, nested emphasis, images, cover order, unique bookmarks, local footnotes and preservation after failure or cancellation. It validates XML with `xmllint`, round-trips the document through Pandoc and restores embedded fonts byte-for-byte to compare them with their sources. It requires Pandoc, `unzip`, `xmllint` and the local font package.
- `test:release` checks the workflow and exercises release operations in local Git repositories. It uses Ruby's standard YAML library and simulates publication. ShellCheck runs in CI.

These tools are development dependencies, not plugin runtime requirements. Browser checks supply native browser element creation and parse the bundled preview samples; they do not exercise Obsidian's DOM helpers, HTML sanitizer, icons, system protocol handling, native file pickers or the complete Obsidian modal. Process checks use POSIX fixtures; Windows search paths are checked without running Windows executables.

## Source layout

[main.ts](../main.ts) loads [plugin/main.ts](../plugin/main.ts). Settings live in [plugin/settings-tab.ts](../plugin/settings-tab.ts), tool detection in [plugin/tools.ts](../plugin/tools.ts), version comparisons in [plugin/updates.ts](../plugin/updates.ts) and settings types in [plugin/types.ts](../plugin/types.ts).

The build produces `main.js` at the repository root. Obsidian loads it with `manifest.json` and `styles.css`.

Bundled resources live under [scripts/lua](../scripts/lua), [scripts/latex](../scripts/latex) and [scripts/epub](../scripts/epub). [scripts/resources.ts](../scripts/resources.ts) imports them as text; esbuild embeds them in `main.js`. No separate filter or template download is needed. [scripts/check-resources.mjs](../scripts/check-resources.mjs) verifies that the compiled bundle contains the source resources unchanged. The thin-space filter escapes XML characters and handles narrow no-break spaces.

## Release workflow

[release.sh](../release.sh) runs from the repository's default branch. It requires Node.js/npm, Git, an authenticated GitHub CLI and `jq`.

The script tests, builds and checks embedded resources, then commits pending changes and pushes the branch. It increments the patch version, synchronises the manifest, package and lockfile, updates `versions.json` when present, commits and pushes that version. It compares the manifest on GitHub with the local file before creating and pushing the numeric version tag.

[The release workflow](../.github/workflows/release.yml) uses pinned actions and artifact attestation. It validates versions, runs the checks and builds twice to verify reproducibility, then publishes `main.js`, `manifest.json` and `styles.css` from the tag. CSS, Lua and LaTeX resources are embedded in the bundle.

Running `bash release.sh` publishes a release. Use `test:release` to exercise the process locally without publishing; actual publication is not part of the local checks.
